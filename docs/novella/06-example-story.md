# 06 — Bundled example story and catalog

> **Revision 11 changes:** the example remains declarative but now supplies deterministic digest/comparator fixtures, a controller-authorized story-switch fixture, and recovery fixtures for successor origin evidence.

Bundle at least one nontrivial story under a versioned catalog entry:

```ts
storyCatalog.get(storyId, storyVersion)
```

The manifest demonstrates dialogue, branching choices, conditions, string/boolean/number variables, effects, converging branches, explicit next links, and a terminal scene. It contains no executable content or raw HTML.

## Required fixtures

- two same-revision states differing only in variables so digest tie-break ordering is testable;
- two object-insertion orders producing identical canonical bytes/digest;
- one same session/epoch state with changed story version that must reject;
- a revision-0 `SESSION_STARTED` switch state usable as `session-started` origin evidence;
- successor evidence with full known state matching its outcome floor;
- successor evidence without full state to exercise floor-only recovery;
- active-epoch reconciled former loser that later progresses farther;
- two sequential controller-departure states for lineage tests.

## Asset references

All asset IDs resolve through the validated story catalog and same-origin allowlist. Missing optional assets degrade visibly; missing required story data blocks that story version.

## Authoring checks

- every referenced scene/entry/choice/asset exists;
- start entry exists;
- transitions and effects are bounded;
- variable defaults satisfy declared conditions/effects;
- story version is immutable after release;
- digest fixtures are generated by the production canonicalizer and frozen in tests.
